# Security Policy

## Supported Versions

NewRssFeed is an open-source project under active development.

Security fixes are generally intended for the latest version available on the `main` branch. Older versions may not receive security updates.

| Version | Supported |
| --- | --- |
| Latest version on `main` | Yes, where applicable |
| Older commits and unreleased snapshots | No guarantee of security updates |

Support status may change as the project evolves and releases are published.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub Issues or public Pull Requests.**

If you discover a potential security vulnerability in NewRssFeed, please report it privately so that it can be investigated before details become public.

### How to Report

1. Open the [NewRssFeed repository](https://github.com/korayozkan/NewRssFeed).
2. Navigate to the **Security** tab.
3. Look for the option to report a vulnerability privately.
4. Submit a report with the details needed to investigate the issue.

If private vulnerability reporting is unavailable, contact the repository maintainer through a private contact method listed on their GitHub profile. Do not disclose sensitive technical details publicly.

### What to Include

Please include as much of the following information as possible:

- **Description:** A clear explanation of the potential vulnerability.
- **Affected components:** The files, features, or versions involved.
- **Steps to reproduce:** Instructions or a proof of concept demonstrating the issue.
- **Impact:** What an attacker might be able to do.
- **Environment:** Relevant browser, operating system, or configuration details.
- **Suggested fix:** If you have a proposed solution, include it.

Please avoid including real user data, passwords, access tokens, or other sensitive information in your report.

## What Happens Next?

The maintainer will review the report, assess its validity and potential impact, and determine the appropriate remediation.

If the vulnerability is confirmed, the maintainer may:

- Investigate and develop a fix.
- Request additional information to reproduce the issue.
- Prepare an updated version or patch.
- Coordinate public disclosure after the issue has been addressed.

Response and resolution times may vary depending on the severity and complexity of the issue and the maintainer's availability.

Please do not assume that a report has been received or accepted until you receive a response.

## Responsible Disclosure

We appreciate security researchers and community members who help keep NewRssFeed safe.

Please give the maintainer a reasonable opportunity to investigate and address a vulnerability before publicly disclosing technical details.

Do not exploit vulnerabilities beyond what is necessary to demonstrate the issue, access other people's data, disrupt services, or compromise systems without authorization.

## Scope

This policy covers security vulnerabilities directly affecting NewRssFeed and the code maintained in this repository.

Issues in third-party services or dependencies may need to be reported to their respective maintainers as well.
