## HIGH (Hard Gate)

### 1. App does not typecheck — pre-existing scaffold components import a missing `styled` export
- Rules: R-35 (verify before deliver), R-33 spirit
- Files: `components/ui/button/index.tsx:10`, `components/ui/input/index.tsx:7`, `components/ui/form-control/index.tsx:7`
- Evidence: `npx tsc --noEmit` exits 1. `error TS2305: Module '"nativewind"' has no exported member 'styled'`, which then cascades into `className does not exist on type` errors at `button/index.tsx:189,201,208`, `form-control/index.tsx:241`, `input/index.tsx:69`. nativewind v4.2.7 (installed) does not export `styled` the way this v3-era scaffold expects.
- Fix: rewire `styled` to the correct source for the installed gluestack v5 + nativewind v4 (e.g. the `styled` HOC from `@gluestack-ui/utils/nativewind-utils` or the current gluestack CLI output), or regenerate these three components from the current CLI.
- Validation: `npx tsc --noEmit` exits 0; the app boots and a screen that renders `Input` does not crash.

### 2. Dead, broken UI components I added (`box`, `center`, `text`) import non-existent creator modules
- Rules: R-35, C-2 (functional completeness)
- Files: `components/ui/box/index.tsx:1`, `components/ui/center/index.tsx:1`, `components/ui/text/index.tsx:1`
- Evidence: `error TS2307: Cannot find module '@gluestack-ui/core/box/creator'` (box, center) and `'@gluestack-ui/core/text/creator'` (text). These three files are also unused: the final auth screens import only `button`, `input`, and `gluestack-ui-provider`, and use React Native `Text`/`View` directly.
- Fix: delete the three unused files (dead code that fails compilation). Re-add a correct version only if a real use appears.
- Validation: after deletion, `npx tsc --noEmit` drops the three TS2307 errors; `grep -r "ui/box\|ui/center\|ui/text" src` finds no import references.

### 5. `explore.tsx` and `profile.tsx` are duplicate placeholder stubs

## MEDIUM (Purpose-Gate)

### 8. Palette bypasses the defined design-token system; three unrelated accent colors
- Rules: R-29 (limit palette), R-20 (visual identity)
- Files: `src/app/login.tsx` (`bg-blue-600`, `text-blue-600`), `src/app/register.tsx` (`bg-green-600`, `text-green-600`), `src/app/forgot-password.tsx` (`bg-orange-500`)
- Evidence: `src/global.css` defines a semantic token system (`--primary`, `--secondary`, `--muted`, `--destructive`, `--accent`, `--foreground`) with no blue/green/orange. The auth screens ignore the system and use raw Tailwind colors, introducing three different accents across three screens with no shared palette. R-29 limits the palette to 2-3 core + 1 accent.
- Fix: use the design tokens (`bg-primary` etc.), or add ONE accent token to `global.css` and use it consistently across all auth screens.
- Validation: `grep -r "blue-600\|green-600\|orange-500" src/app` returns nothing; accent comes from tokens.

### 9. No safe-area handling; content can collide with notches and the home indicator
- Rules: R-03 (mobile responsiveness), C-4 (resilience)
- Files: `src/app/login.tsx`, `src/app/register.tsx`, `src/app/forgot-password.tsx`
- Evidence: the screens use a `ScrollView` with `py-12` and vertically-centered content but no `SafeAreaView` or safe-area insets; on notched devices the top content can sit under the status bar and the bottom under the home indicator.
- Fix: wrap each screen in `SafeAreaView` (from `react-native-safe-area-context`) or apply safe-area padding.
- Validation: run on a notched device/simulator; confirm content clears the status bar and home indicator.

### 10. Tap targets at or below the 44px minimum
- Rules: R-03
- Files: `src/app/register.tsx` (the 20x20 custom checkbox `View`), `src/app/login.tsx` / `register.tsx` / `forgot-password.tsx` (the password eye-toggle `InputSlot`)
- Evidence: the custom checkbox is 20x20px; the eye-toggle `InputSlot` width is roughly icon(18) + padding(12), about 30px. R-03 requires 44px minimum tap targets. (The checkbox `Pressable` wraps the whole row so its effective height is larger, but the visual target is small.)
- Fix: increase the visual and tappable target to at least 44x44 (a 44x44 `Pressable` hit area around the checkbox; widen the eye-toggle slot).
- Validation: tap each control; measure the hit area, confirm >= 44px.

## LOW (Quality Locks / Craftsmanship)

### 11. Lucide glyph used as the product logo
- Rules: R-04, C-1
- Files: same as #6
- Evidence: a lucide icon inside a colored rounded box is used as the logo; lucide is the default icon-set look. The field icons (Mail/Lock/User/Eye) are relevant to their fields and are fine; the issue is only the logo misuse.
- Fix: covered by #6 (remove the logo box).
- Validation: no lucide glyph used as a logo.

### 12. Border radius used as a near-uniform default, not as hierarchy
- Rules: R-11, C-1
- Files: auth screens (`rounded-2xl` on cards and the 16x16 logo box, `rounded-xl` on buttons, inputs inherit `rounded-md`)
- Evidence: cards, buttons, and the logo box all use one large radius; the logo box matches the card radius so it does not differentiate hierarchy.
- Fix: vary radius deliberately (e.g. card `rounded-xl`, button `rounded-lg`) and write the reason, or justify the uniform large radius as an identity choice in `DESIGN.md`.
- Validation: radius values reviewed; hierarchy reason written.

### 13. Decorative emoji in headings and success states with no stated purpose
- Rules: C-1 (intentionality)
- Files: `src/app/login.tsx` ("Hoş Geldiniz 👋"), `src/app/register.tsx` ("Hesap Oluştur 🚀", Alert "Başarılı 🎉"), `src/app/forgot-password.tsx` ("Email Gönderildi ✉️", "✓")
- Evidence: emoji used as decoration; no UX purpose written. This would be fine if a `DESIGN.md` endorsed it.
- Fix: remove the emoji or justify them via direction.
- Validation: emoji removed or justified by `DESIGN.md`.

### 14. `tailwind.config.js` is the empty v3 default, inconsistent with the v4 CSS setup in use
- Rules: R-05 / maintainability
- File: `tailwind.config.js`
- Evidence: `content: []`, no `theme.extend`, no safelist. The project actually uses Tailwind v4 via `@theme inline` in `global.css`. The stale v3 config can confuse the build and linters.
- Fix: remove `tailwind.config.js` (Tailwind v4 is configured via CSS) or update it to match the v4 setup.
- Validation: build runs without purge warnings; no stale v3 config conflict.

### 15. `as never` casts bypass the strict typed-routes type system
- Rules: R-35 / maintainability
- Files: `src/app/login.tsx` (`router.push("/forgot-password" as never)`, `"/register" as never`), `src/app/register.tsx` (`"/login" as never`), `src/app/forgot-password.tsx` (`"/login" as never`)
- Evidence: `app.json` enables `experiments.typedRoutes: true`; the casts silence the `Type '"/x"' is not assignable to RelativePathString` error rather than fixing the route map.
- Fix: regenerate typed routes (restart Metro so `.expo/types/router.d.ts` rebuilds) so the real routes typecheck without `as never`, then remove the casts.
- Validation: `npx tsc --noEmit` clean with the casts removed.
